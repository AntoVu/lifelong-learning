Graphs: breadth-first and depth-first search

Lists line things up, and trees branch out from one root. Graphs drop the rules: anything can connect to anything. Road maps, social networks, the web, and the packages your code depends on are all graphs, and two simple strategies for exploring them, breadth-first and depth-first search, solve a surprising number of problems.

Breadth-first search spreads out evenly, like ripples, and the path it finds is always as short as possible. Depth-first search charges down one corridor until it hits a dead end, then backs up; it finds a path, often a long winding one. The only difference in the code is one line.

What a graph is

A graph is a set of nodes (also called vertices) and edges connecting pairs of them. Edges can be undirected (friendship goes both ways) or directed (you follow someone who doesn't follow you; a web page links to another). They can also be weighted, with a number like distance or cost, which is the next lesson. A path that comes back to where it started is a cycle. A tree is just a connected graph with no cycles.

Storing a graph

The usual choice is an adjacency list: for each node, a list of its neighbors. In Python that's a dict of lists, like the one in the figure. It takes O(V + E) space, and listing a node's neighbors costs only as much as the number of neighbors.

The alternative is an adjacency matrix: a V × V grid of true/false, where row u, column v says whether u connects to v. It answers "is there an edge from u to v?" in O(1), but it takes V² space even if there are hardly any edges. Most real graphs are sparse: a social network with a billion people would need a billion × billion matrix, while each person has a few hundred friends. So lists win most of the time.

Breadth-first search

Breadth-first search (BFS) explores from a start node in rings: first all the nodes one edge away, then all the nodes two edges away, and so on. It keeps the nodes waiting to be explored in a queue (lesson 2), so the ones discovered first get explored first:

from collections import deque

def bfs(graph, start):
    dist = {start: 0}               # also serves as the "visited" set
    queue = deque([start])
    while queue:
        u = queue.popleft()          # oldest discovery first
        for v in graph[u]:
            if v not in dist:
                dist[v] = dist[u] + 1
                queue.append(v)
    return dist

Because it reaches every node at distance 1 before any node at distance 2, the first time BFS reaches a node is by a shortest path, counted in edges. That's why it's the tool for "fewest hops" questions: degrees of separation in a social network, fewest moves in a puzzle, fewest stops on a subway map. Each node enters the queue once and each edge is checked once (twice if undirected), so BFS runs in O(V + E).

Depth-first search

Depth-first search (DFS) does the opposite: follow one edge, then one edge from there, as deep as possible, and only back up when stuck. It's the recursion from stage 2, and the call stack is its stack:

def dfs(graph, u, visited=None):
    if visited is None:
        visited = []
    visited.append(u)
    for v in graph[u]:
        if v not in visited:
            dfs(graph, v, visited)   # go deeper before trying u's other neighbors
    return visited

Swap BFS's queue for a stack and you get DFS's order too; that's the one-line difference the maze shows. DFS also costs O(V + E). It doesn't find shortest paths, but it's the natural tool for questions about structure: is everything connected? Is there a cycle? Which pieces depend on which? It's also how most maze generators and puzzle solvers work, since it explores one complete possibility at a time. (One practical note: for real code, use a set for visited, not a list; in on a list is O(n), as lesson 1 warned.)

Practice 4

Run the recursive dfs on the example graph from A, with neighbors in alphabetical order. In what order are the nodes visited?

HintFrom A go to B, from B to D. D's neighbors are B, C, and F, in that order. Which comes first that isn't visited yet?

A B D C E F. A → B → D → C (D's first unvisited neighbor) → E → F. Then every call returns, finding nothing new. Compare BFS's A B C D E F: same graph, very different route.

Check

You want the fewest friend-of-a-friend hops between two people in a social network. Which search?

BFS: it explores everyone 1 hop away, then 2, then 3, so it reaches the target by the fewest hops. LinkedIn's "2nd" and "3rd" connection labels are this idea.

Ordering dependencies

A directed acyclic graph (DAG), a directed graph with no cycles, describes dependencies: course prerequisites, build steps, spreadsheet cells, package installs. To act on it you need a topological order: a list where everything comes after the things it depends on. DFS produces one: finish exploring a node's dependencies, then add the node. Python has it built in:

from graphlib import TopologicalSorter

needs = {"deploy": {"test", "build"}, "test": {"build"}, "build": {"install"}}
list(TopologicalSorter(needs).static_order())
# ['install', 'build', 'test', 'deploy']

If the graph has a cycle (A needs B and B needs A), there's no valid order, and the sorter raises an error. That's how package managers detect circular dependencies.

Where this idea started

The bridges of Königsberg, 1736

The Prussian city of Königsberg sat on both banks of a river and two islands, joined by seven bridges. Residents wondered whether you could walk through the city crossing each bridge exactly once. Leonhard Euler proved you can't, and the proof founded graph theory. Euler threw away everything about the map except which land masses each bridge joined: four nodes and seven edges. The key observation: a walk entering and leaving a land mass uses its bridges in pairs, so all but the start and end must touch an even number of bridges. All four of Königsberg's touched an odd number. The modern lesson is the same as Euler's: once you strip a problem down to a graph, a whole toolbox of algorithms applies.

What to remember

  • A graph is nodes and edges: directed or not, weighted or not. Trees are graphs without cycles.
  • Use an adjacency list (dict of lists) unless the graph is small or dense.
  • BFS uses a queue, explores in rings, and finds shortest paths in unweighted graphs.
  • DFS uses a stack (or recursion), goes deep first, and answers structure questions.
  • Both cost O(V + E). Track visited nodes in a set.
  • A topological order lists a DAG's nodes so dependencies come first.

Try it in Python

Find the shortest path itself, not just its length, by remembering where each node was reached from:

from collections import deque

def shortest_path(graph, start, goal):
    came_from = {start: None}
    queue = deque([start])
    while queue:
        u = queue.popleft()
        if u == goal:
            path = []
            while u is not None:
                path.append(u)
                u = came_from[u]
            return path[::-1]
        for v in graph[u]:
            if v not in came_from:
                came_from[v] = u
                queue.append(v)
    return None

g = {"A": ["B", "C"], "B": ["A", "D"], "C": ["A", "D", "E"],
     "D": ["B", "C", "F"], "E": ["C", "F"], "F": ["D", "E"]}
print(shortest_path(g, "A", "F"))    # ['A', 'B', 'D', 'F']
