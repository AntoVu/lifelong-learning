Shortest paths

Breadth-first search finds the route with the fewest hops. But on a real map, some roads are long and some are short, and the fewest turns isn't the quickest drive. This lesson adds lengths to the edges, and works through the algorithm behind route planners and internet routers: Dijkstra's.

Weighted graphs

In a weighted graph, every edge carries a number: kilometers, minutes, dollars, milliseconds of network delay. The length of a path is the sum of its edge weights, and the shortest path is the one with the smallest sum. BFS counts edges, so it treats a 1-minute road and a 60-minute road the same. It's only right when every edge has the same weight.

Dijkstra's algorithm

Edsger Dijkstra's idea (1956) is to grow the set of nodes whose shortest distance is known, always adding the closest one next. Every node gets a tentative distance, starting at 0 for the source and infinity for everything else. Then repeat:

  1. Take the unfinished node u with the smallest tentative distance. Its distance is now final.
  2. Relax each edge from u: if going through u gives a neighbor v a shorter route, update v's distance to dist[u] + weight(u, v) and remember that v is reached from u.
import heapq

def dijkstra(graph, source):              # graph[u] = [(v, weight), ...]
    dist = {source: 0}
    pq = [(0, source)]                    # a min-heap of (distance, node), lesson 5
    done = set()
    while pq:
        d, u = heapq.heappop(pq)
        if u in done:
            continue                      # an outdated entry; skip it
        done.add(u)
        for v, w in graph[u]:
            if d + w < dist.get(v, float("inf")):
                dist[v] = d + w           # relax: found a shorter route to v
                heapq.heappush(pq, (d + w, v))
    return dist

The heap from lesson 5 is what makes "take the closest unfinished node" fast. Each edge may push one entry, and each push or pop costs O(log V), so the whole thing runs in O((V + E) log V). That's fast enough for road networks with millions of intersections.

HintIs 5 + 3 smaller than 10?

5 + 3 = 8, which beats 10, so v is updated to 8 and marked as reached from u. If the edge weighed 7, then 12 would lose to 10 and nothing would change.

Why it works, and when it doesn't

Why is it safe to call the closest unfinished node final? Any other route to it would have to leave the finished set through some other unfinished node, which is already at least as far away, and then add more edges. Since edge weights are never negative, adding edges can't make a route shorter. So nothing can ever beat the current distance. That's a greedy algorithm: it makes the locally best choice and never revisits it, and here that's provably correct.

The proof leans on "never negative". With a negative edge, like a toll road that pays you, a route could get shorter by going further, and Dijkstra's early decisions can be wrong. For those graphs there's the Bellman-Ford algorithm, which relaxes every edge V − 1 times, O(V · E). It's slower, but it handles negative edges and can even detect a negative cycle, a loop you could go around forever to make the "distance" smaller without limit.

Check

Why can Dijkstra's algorithm finalize the closest unfinished node right away?

Non-negative weights. Every other route must pass through a node that's already at least as far, and adding edges can only add distance. Remove that guarantee and the argument, and the algorithm, fails.

Check

A currency trading graph uses edge weights that can be negative. Which algorithm should find the cheapest path?

Bellman-Ford. And its negative-cycle detection is useful here: in currency exchange (with weights set to the negative logarithm of each rate), a negative cycle is an arbitrage loop that turns a dollar into more than a dollar.

A*: searching toward the goal

Dijkstra's algorithm spreads out in every direction, like BFS's ripples. If you only want the route from Chicago to New York, it wastes effort finalizing towns west of Chicago. A* ("A star", 1968) fixes that by ordering the priority queue by distance so far plus a guess of the distance remaining, such as the straight-line distance to the goal. Nodes in the right direction get explored first.

The guess, called a heuristic, must never overestimate the real remaining distance. Straight-line distance qualifies, since no road is shorter than a straight line. With such a heuristic, A* still finds the true shortest path, usually after exploring far fewer nodes. It's the standard pathfinding algorithm in video games. Map apps go further still: they preprocess the road network once, adding shortcuts between important junctions, so each query only searches a small part of the map.

Check

For A* on a road map, why is straight-line distance a safe heuristic?

A heuristic that never overestimates (called admissible) keeps A* correct. A guess of 0 is also admissible; then A* is exactly Dijkstra.

Where this idea came from

Twenty minutes in a café, 1956

Dijkstra designed his algorithm to demonstrate a new computer at the Mathematical Centre in Amsterdam, and wanted a problem that people without a math background could understand: the shortest route between two Dutch cities. Years later he recalled that he designed it one morning while shopping in Amsterdam with his fiancée, sitting on a café terrace with a cup of coffee, in about twenty minutes and without pencil and paper. He said avoiding pencil and paper forced him to keep it simple. It was published in 1959 in a three-page paper, and today versions of it run inside internet routers (the OSPF routing protocol computes routes this way) and behind every navigation app.

What to remember

  • With weighted edges, the shortest path minimizes total weight, not hops. BFS only works when all weights are equal.
  • Dijkstra: repeatedly finalize the closest unfinished node and relax its edges. Use a heap: O((V + E) log V).
  • It's correct because weights are non-negative. With negative edges, use Bellman-Ford, O(V · E).
  • A* adds a heuristic guess of the remaining distance; if it never overestimates, A* stays correct and searches less.

Try it in Python

Run the dijkstra function above on the panel's graph:

edges = [("A", "B", 4), ("A", "C", 2), ("B", "C", 1), ("B", "D", 5), ("C", "D", 8),
         ("C", "E", 10), ("D", "E", 2), ("D", "F", 6), ("E", "F", 3)]
graph = {}
for a, b, w in edges:
    graph.setdefault(a, []).append((b, w))
    graph.setdefault(b, []).append((a, w))     # undirected: both directions

print(dijkstra(graph, "A"))
# {'A': 0, 'B': 3, 'C': 2, 'D': 8, 'E': 10, 'F': 13}
