Bits, bytes, and how everything becomes a number

Every photo, song, message, and program on your computer is stored as a long row of switches that are either on or off. This lesson shows how a row of switches can mean a number, a negative number, a letter, or a fraction.

Why only two states?

Inside a chip, information is electricity. A wire carries a voltage, and the hardware reads it. You could try to use ten voltage levels to store the digits 0 to 9 directly, but real signals are noisy: heat, interference, and tiny manufacturing differences push the voltage around. With ten levels packed close together, a little noise turns a 6 into a 7.

With only two levels, there's a wide safety margin. Anything above a threshold is a 1 and anything below it is a 0. The signal can wobble a lot and still be read correctly.

One on/off value is a bit (short for binary digit). Eight bits make a byte, the smallest chunk most computers can address in memory. Everything else in this lesson is about agreeing on what a pattern of bits means. The bits themselves don't know if they're a number, a letter, or a pixel. The program decides.

Place value in base 2

You already know how base 10 works, even if you never think about it. In 407, each column is worth ten times the column to its right:

Column worth1000100101 Base 1004074×100 + 7×1 = 407 Column worth8421 Base 210118 + 2 + 1 = 11

Binary is the same idea with only two digits, so each column is worth twice the one to its right: 1, 2, 4, 8, 16, 32, 64, 128. To read a binary number, add up the column values wherever there's a 1. That's exactly what the sum line on the switch panel does.

Decimal to binary

To go the other way, take the largest power of two that fits, subtract it, and repeat with what's left. For 45:

  • 32 fits, leaving 13. Put a 1 in the 32 column.
  • 16 doesn't fit in 13. Put a 0 there.
  • 8 fits, leaving 5. Then 4 fits, leaving 1. 2 doesn't fit. 1 fits, leaving 0.

Reading the columns from 32 down to 1 gives 101101. Check it: 32 + 8 + 4 + 1 = 45.

How much fits, and overflow

Each extra bit doubles the number of patterns. One bit has 2 patterns, two bits have 4, three have 8. In general, n bits give 2n patterns. If you use them for counting from zero, the largest value is 2n − 1, because zero takes one of the patterns.

A handy shortcut: 210 = 1,024, which is close to 1,000. So 220 is about a million, 230 about a billion, and 232 is 4 × 230, about 4 billion.

What happens when you're at the largest value and add 1? Set all eight switches on the panel to 1 (that's 255), then press Add 1. Like a car odometer rolling from 999,999 to 000,000, the bits all carry over and the extra 1 falls off the left end. This is overflow, and the value wraps around to 0.

Check

An 8-bit unsigned counter holds 255. A program adds 1 to it. On typical hardware, what does the counter hold afterward?

11111111 + 1 = 1 00000000. The ninth bit doesn't fit, so the byte holds 0. Languages handle this differently: unsigned math in C wraps silently, Rust panics in debug builds, and Python's integers simply grow to as many bits as they need. Knowing which one you're using matters.

Hexadecimal

Long rows of 1s and 0s are hard for people to read. Hexadecimal (base 16) fixes this. Four bits have exactly 16 patterns, so each group of four bits maps to one hex digit. Hex needs 16 digits, so after 0 to 9 it borrows the letters A to F.

0000010001200103001140100501016011070111 8100091001A1010B1011C1100D1101E1110F1111

Code marks hex with a 0x prefix so it isn't mistaken for decimal: 0xB6 is 182. You'll see hex everywhere: memory addresses in a debugger, Git commit hashes, and colors in CSS. The highlighter yellow on this page is #F6E15A, which is three bytes: red F6 (246), green E1 (225), and blue 5A (90).

To convert hex to decimal, use place value with 16s: 0x2F = 2 × 16 + 15.

Negative numbers

So far every pattern meant a value of zero or more. To store negative numbers, we need to give some patterns a negative meaning. The obvious idea is to use the leftmost bit as a sign (0 for plus, 1 for minus), but that has two problems. It produces two zeros (+0 and −0), and the adder circuit needs special cases for signs.

Almost every computer instead uses two's complement. The rule is small: the leftmost bit's column is worth negative its usual value. In a byte, that column is worth −128 instead of 128. Everything else is unchanged.

Tick Read the leftmost bit as −128 on the switch panel and try a few patterns. 10000000 becomes −128, the most negative value. 11111111 becomes −128 + 127 = −1. A byte now covers −128 to 127: still 256 values, just shifted.

That wheel shows why hardware loves two's complement: adding is the same operation either way. The circuit just adds bits and doesn't care whether you meant them as signed. Only the place where you wrap around moves.

Negating a number

To get −x from x: flip every bit, then add 1. For −5:

  5  =  00000101
flip =  11111010
 +1  =  11111011   ← this is −5

Check it with the column values: −128 + 64 + 32 + 16 + 8 + 2 + 1 = −5.

Practice 5

Write −20 as an 8-bit two's complement number.

HintWrite 20 as eight bits first (16 + 4), then flip every bit and add 1.

20 = 00010100. Flip: 11101011. Add 1: 11101100. Check: −128 + 64 + 32 + 8 + 4 = −20.

Check

A signed 32-bit integer holds 2,147,483,647, its largest value. You add 1. What do you get on typical hardware?

It's the 4-bit wheel at a bigger scale: the largest positive value is 0111…1, and adding 1 gives 1000…0, the most negative value, −2,147,483,648. In C this is undefined behavior for signed integers, which is worse than wrapping: the compiler may assume it never happens.

Text: ASCII, Unicode, and UTF-8

Text works the same way: everyone agrees on a table that gives each character a number. The first widely used table was ASCII (1963). It uses 7 bits for 128 characters: English letters, digits, punctuation, and control codes like newline. In ASCII, A is 65 and a is 97. Try 65 on the switch panel (01000001).

Lowercase is exactly 32 more than uppercase, and 32 is a single bit (00100000). Changing a letter's case in ASCII just flips one switch. Try it on the panel: switch between 01000001 and 01100001.

128 characters is enough for English and nothing else. Unicode is the modern table. It gives a number, called a code point, to nearly 160,000 characters from every major writing system, plus symbols and emoji. Code points are written U+ followed by hex. A is still U+0041 (65), é is U+00E9, and 😀 is U+1F600.

Unicode only says which number each character gets. An encoding decides how to store that number as bytes. The one the web runs on is UTF-8. It uses 1 to 4 bytes per character, and the first bits of each byte tell the reader how many bytes belong together:

Practice 6

How many bytes does the word café take in UTF-8?

HintThree of the letters are plain ASCII. Where does U+00E9 fall in the table?

c, a, and f take 1 byte each. é (U+00E9) is above U+007F, so it takes 2 bytes: C3 A9. Total: 5. That's why a database column limited to "4 bytes" can't hold this 4-letter word.

Fractions and floating point

Binary can have a point too, like a decimal point. To the right of it, columns are worth ½, ¼, ⅛, and so on. So 0.101 in binary is ½ + ⅛ = 0.625.

Here's the catch. In base 10 you can't write ⅓ exactly; it's 0.333… forever. In base 2 you can't write 0.1 exactly. It becomes 0.000110011001100… repeating, and the computer has to cut it off somewhere. So the stored value is very slightly off.

Most languages store fractional numbers as floating point, using the IEEE 754 standard. It's scientific notation in base 2. A 64-bit "double" splits its bits into three parts:

Floating-point lab

This uses your browser's real 64-bit math. Try 0.1 + 0.2, then 0.5 + 0.25.

0.5 and 0.25 are exact powers of two, so they're stored perfectly and the sum is exact. 0.1 and 0.2 aren't, so two tiny errors add up to a visible one. Neither result is a bug. It's how floating point is designed. Three habits follow from it:

  • Don't compare floats with ==. Check whether they're within a small tolerance, like Python's math.isclose(a, b).
  • Don't store money in floats. Use whole cents as integers, or a decimal type such as Python's Decimal or SQL's DECIMAL.
  • Mind the integer limit in JavaScript. Every JS number is a double, so integers are only exact up to 253 − 1. Use BigInt beyond that.
Check

You're building a checkout page. How should you store a price of $19.99?

Integers are exact, so 1999 cents adds and compares perfectly. A decimal type (like DECIMAL(10,2) in SQL) is also fine. Convert to dollars only when you display the value.

When this goes wrong

These aren't textbook curiosities. Each of these happened because a value didn't fit in the bits it was given.

Ariane 5, 1996

Forty seconds after launch, a rocket's guidance software converted a 64-bit floating-point value to a 16-bit signed integer. The value was larger than 32,767, the conversion failed, the guidance system shut down, and the rocket was destroyed. The code had been reused from Ariane 4, which never flew fast enough to hit the limit.

The Patriot missile clock, 1991

A missile defense system counted time in tenths of a second and stored 0.1 in a 24-bit register. Since 0.1 isn't exact in binary, each tick lost a tiny amount. After 100 hours of running, the clock was off by about a third of a second, enough to miss an incoming missile in Dhahran, Saudi Arabia. Twenty-eight soldiers died.

Gangnam Style, 2014

YouTube's view counter used a signed 32-bit integer. When the video neared 2,147,483,647 views, YouTube switched the counter to 64 bits before it could wrap around to a negative number.

The year 2038

Many systems store time as seconds since January 1, 1970, in a signed 32-bit integer. That runs out at 03:14:07 UTC on January 19, 2038, and wraps to December 1901. Modern systems use 64 bits, but old embedded devices and file formats are still out there.

What to remember

  • A bit is one on/off value. Meaning comes from how a program interprets a pattern of bits.
  • n bits give 2n patterns. Go past the largest value and it wraps around.
  • One hex digit is exactly four bits, which is why engineers read bytes in hex.
  • Two's complement makes the top bit negative, so the same adder works for signed and unsigned numbers.
  • Unicode numbers the characters; UTF-8 turns those numbers into 1 to 4 bytes.
  • Floating point is approximate. Compare with a tolerance, and keep money in integers or decimals.
