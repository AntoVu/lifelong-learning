Trees, binary search trees, and heaps

A sorted list makes searching fast (binary search) but inserting slow (shift everything). A hash table makes both fast but forgets order. Trees keep data in order and stay fast to change, as long as they stay bushy. This lesson shows how, and what happens when they don't.

Trees

A tree is a set of nodes where each node has some children and exactly one parent, except the top one, the root. Nodes with no children are leaves. You've met several already: folders on a disk, the call tree of fib, the parse tree of the interpreter, and every web page's HTML. A tree's height is the number of levels from the root to its deepest leaf. In a binary tree, each node has at most two children, left and right.

Trees are naturally recursive: each child is the root of a smaller tree. So most tree code is a short recursive function with "empty tree" as the base case, exactly the leap of faith from stage 2.

Binary search trees

A binary search tree (BST) adds one rule: for every node, everything in its left subtree is smaller, and everything in its right subtree is larger. That rule turns every node into a binary-search decision:

class Node:
    def __init__(self, key):
        self.key, self.left, self.right = key, None, None

def search(node, key):
    while node is not None:
        if key == node.key:
            return node
        node = node.left if key < node.key else node.right   # discard one side
    return None

def insert(node, key):
    if node is None:
        return Node(key)                      # found the empty spot
    if key < node.key:
        node.left = insert(node.left, key)
    elif key > node.key:
        node.right = insert(node.right, key)
    return node

Each step goes down one level, so search and insert take at most h steps, where h is the height. For a well-shaped tree with n nodes, h is about log₂ n. A balanced tree of a million keys is only about 20 levels tall.

Practice 1

A perfectly balanced BST holds 1,023 keys (every level full). At most how many nodes does a search look at?

HintFull levels hold 1, 2, 4, 8, ... nodes. How many levels add up to 1,023?

1 + 2 + 4 + ... + 512 = 1,023, which is 10 levels, so at most 10 nodes: one per level, root to leaf. That's the same count as binary search on a sorted list of 1,023 items, and no coincidence.

Height is everything

A BST's shape depends on the order keys arrive. Insert sorted keys and each new one is bigger than everything so far, so it always goes right: the tree becomes a chain with height n, and searching it is O(n). Sorted input is common in real life (timestamps, IDs, alphabetical imports), so this isn't a rare accident.

Practice 2

You insert 1, 2, 3, 4, 5, 6, 7 into an empty BST in that order. What is the tree's height, counted in levels?

HintTry it in the panel. Where does each new key go?

7: every key is the right child of the one before. Inserted as 4, 2, 6, 1, 3, 5, 7, the same keys make a tree of height 3.

Self-balancing trees fix this by rearranging themselves with small local moves called rotations whenever an insert or delete makes them lopsided, guaranteeing a height of O(log n). The classic designs are AVL trees (1962) and red-black trees (1978). You rarely write one yourself, but you use them constantly: Java's TreeMap is a red-black tree, as C++'s std::map usually is, and databases use a wide, shallow cousin called the B-tree (stage 7).

Check

Why use a balanced BST instead of a hash table?

Order. "All orders from last Tuesday to today" or "the next appointment after 3 PM" are fast in a BST and slow in a hash table, which would have to check every key. When you only need exact lookups, use the hash table.

Traversals

To visit every node, recurse into both children. The three classic orders differ only in when you handle the node itself:

def in_order(node):              # left, node, right
    if node:
        in_order(node.left)
        print(node.key)
        in_order(node.right)

# pre-order:  node, left, right   (copy a tree, print a folder outline)
# post-order: left, right, node   (delete a tree, total up folder sizes)

In-order traversal of a BST prints the keys in sorted order, because everything left of a node is smaller and everything right is larger. That gives yet another sorting algorithm: insert everything into a balanced BST, then read it in order, for O(n log n) in total.

Practice 3

Insert 5, 3, 8, 1, 4 into an empty BST. What does an in-order traversal print?

HintYou can skip drawing the tree: what does in-order always give for a BST?

1 3 4 5 8, sorted. Pre-order would print 5 3 1 4 8 (root first), which records the tree's shape and lets you rebuild it.

Heaps and priority queues

Sometimes you don't need everything sorted, only quick access to the smallest item, again and again: the next event in a simulation, the most urgent job, the closest unvisited city in the shortest-path lesson. That's a priority queue, and the standard way to build one is a binary heap.

A min-heap is a binary tree with a weaker rule than a BST: every node is smaller than its children. So the root is the minimum. The tree is always filled level by level, left to right, which means it can live in a plain array with no pointers at all: the children of index i are at 2i + 1 and 2i + 2.

To add an item, put it at the end of the array and swap it up while it's smaller than its parent. To remove the minimum, move the last item to the root and swap it down below its smaller child. Both walk one path, so both are O(log n). Python's heapq module does this on a plain list:

import heapq
tasks = []
heapq.heappush(tasks, (2, "write report"))
heapq.heappush(tasks, (1, "fix outage"))
heapq.heappush(tasks, (3, "lunch"))
heapq.heappop(tasks)       # (1, 'fix outage'): smallest priority first
Practice 4

In a heap stored as an array, what is the index of the left child of the node at index 3?

HintLeft child: 2i + 1.

2 × 3 + 1 = 7, and the right child is at 8. Going back up, (7 − 1) // 2 = 3. No pointers needed, which also makes heaps cache-friendly.

Practice 5

You heappush 5, 1, 8, 3 onto an empty list, in that order. What does heappop return?

HintA min-heap always gives back the smallest item, whatever the insertion order.

1. The list left behind is [3, 5, 8], still a valid heap. Pop again and you get 3.

Check

Which job is a heap bad at?

Searching for an arbitrary value. The heap rule says nothing about left versus right, so 42 could be anywhere: O(n). Use a set for membership, a BST for order, and a heap for "what's next".

Where trees run your computer

The Linux scheduler's red-black tree

Your operating system constantly decides which of hundreds of ready programs gets the CPU next. In 2007, Linux adopted the Completely Fair Scheduler, which kept every runnable task in a red-black tree ordered by how much CPU time it had received. The next task to run was simply the leftmost node, the one that had waited the most, and inserting a task back after its turn cost O(log n) however many tasks there were. In 2023, Linux 6.6 began moving to a newer scheduler called EEVDF, which still keeps tasks in a red-black tree, with extra information stored in each node. Stage 5 covers schedulers in depth; the data structure underneath is the one from this lesson.

What to remember

  • A BST keeps smaller keys left and larger keys right. Search and insert cost O(height).
  • Balanced, the height is about log₂ n. Sorted inserts make a chain of height n.
  • Self-balancing trees (AVL, red-black) guarantee O(log n) and keep keys in order.
  • In-order traversal of a BST visits keys in sorted order.
  • A heap keeps the minimum on top, lives in an array, and pushes and pops in O(log n). Use heapq.

Try it in Python

The k largest items of a big list, without sorting all of it:

import heapq, random

scores = [random.randint(0, 1_000_000) for _ in range(1_000_000)]
print(heapq.nlargest(5, scores))     # uses a small heap of size 5: O(n log 5)
