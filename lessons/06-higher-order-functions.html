Higher-order functions

Stage 1 ended with a small idea: a function is a value you can pass around. This lesson takes that idea seriously. Functions that take or return other functions let you name a whole pattern of computation, not just a single calculation.

Naming a pattern

Here are two functions that look different but share most of their code:

def sum_naturals(n):
    total, k = 0, 1
    while k <= n:
        total, k = total + k, k + 1
    return total
def sum_cubes(n):
    total, k = 0, 1
    while k <= n:
        total, k = total + k**3, k + 1
    return total

The only difference is what gets added each time: k in one, k**3 in the other. A higher-order function is a function that takes another function as an argument (or returns one). Here it lets you write the loop once and pass in the part that changes:

def summation(n, term):
    total, k = 0, 1
    while k <= n:
        total, k = total + term(k), k + 1
    return total

def cube(x):
    return x * x * x

summation(3, cube)       # 1 + 8 + 27 = 36

This is the same move as writing a function in the first place, one level up. A function names a computation; a higher-order function names a shape of computation, with a hole where the details go. This example comes from Berkeley's CS61A, which builds a whole course on it.

Practice 1

Using the summation above, what does summation(3, lambda k: k * k) return?

HintThe term function squares each k, for k = 1, 2, 3.

1 + 4 + 9 = 14. You've built a sum-of-squares function without writing a new loop.

Lambda expressions

Defining a named function just to pass it once is clumsy. A lambda expression creates a small function right where you need it:

square = lambda x: x * x      # same as: def square(x): return x * x
summation(3, lambda k: k * k)

A lambda's body must be a single expression, and its value is what the function returns. There's no return keyword and no room for statements. That's deliberate. If the logic needs more than one line, it deserves a name and a def. The name "lambda" comes from Alonzo Church's lambda calculus, a 1930s model of computation built from nothing but functions.

Practice 2

What does (lambda x, y: x * y)(3, 4) evaluate to?

HintThe parentheses around the lambda create a function; the (3, 4) after it calls it immediately.

12. A lambda is an expression whose value is a function, so you can call it on the spot. You'll rarely write this in real code, but it shows that a lambda is just a function value.

Map, filter, and reduce

Three patterns show up so often that every language has them built in:

PatternIn PythonWhat it does
Mapmap(f, xs)Apply f to every item: [1, 2, 3] → [f(1), f(2), f(3)]
Filterfilter(p, xs)Keep the items where p(x) is true
Reducefunctools.reduce(f, xs)Combine all the items into one value, two at a time: f(f(f(1, 2), 3), 4)

The common reductions have their own names: sum, max, min, any, all. In Python 3, map and filter return lazy iterators, which produce items only as you ask for them, so wrap them in list(...) to see everything at once.

Python also has a shorter syntax for map-and-filter, the list comprehension. Most Python programmers prefer it, because it reads left to right:

list(map(lambda x: x * x, filter(lambda x: x % 2 == 0, nums)))
[x * x for x in nums if x % 2 == 0]          # same result

Try both in the pipeline at the top: it shows the comprehension whenever your steps fit one.

Practice 3

What does list(filter(lambda n: n % 3 == 0, range(10))) return?

Hintrange(10) is 0 to 9. Keep the numbers divisible by 3, and don't forget 0.

[0, 3, 6, 9]. 0 % 3 is 0, so 0 counts. As a comprehension: [n for n in range(10) if n % 3 == 0].

Check

Which comprehension gives the same list as list(map(f, filter(p, xs)))?

[f(x) for x in xs if p(x)]. The if clause filters on the original item, then the expression at the front transforms the survivors. Read the nested calls from the inside out: filter first, then map.

Functions that return functions

A higher-order function can also build a function and hand it back:

def make_adder(n):
    def adder(k):
        return k + n
    return adder

add_three = make_adder(3)
add_three(4)       # 7

Something odd happens here. By the time you call add_three(4), the call to make_adder has returned and its frame is gone from the stack (lesson 5). Yet adder still knows that n is 3. That's because a function defined inside another function keeps a reference to the variables of the frame it was created in. The function plus those remembered variables is called a closure.

Practice 4

With def compose(f, g): return lambda x: f(g(x)), what does compose(lambda x: x * x, lambda x: x + 1)(3) return?

Hintf(g(x)) runs g first. Here g adds 1 and f squares.

g(3) = 4, then f(4) = 16. compose takes two functions and returns a new one, which closes over both f and g.

Check

A classic trap. What does this print?

fs = [lambda: i for i in range(3)]
print(fs[0]())

2. A closure remembers the variable, not its value at the time. All three lambdas share the same i, and by the time you call one, the loop has finished with i = 2. The usual fix captures the current value as a default argument, which is evaluated when the lambda is created: lambda i=i: i. JavaScript had the same bug with var in loops, which is one reason let was added.

Decorators

Put the two ideas together, a function that takes a function and returns a new function, and you get a decorator: a way to add behavior around a function without changing its code.

def logged(f):
    def wrapper(*args):
        print("calling", f.__name__, "with", args)
        return f(*args)
    return wrapper

@logged                  # means: square = logged(square)
def square(x):
    return x * x

square(4)                # prints: calling square with (4,)  and returns 16

The @ line is shorthand for reassigning the name to the wrapped version. Python's standard library uses decorators for caching (@functools.cache, in the next lesson), web frameworks use them to connect URLs to functions (@app.route("/")), and test frameworks use them to mark tests.

Check

Which line means exactly the same as putting @timer above def run(): ...?

run = timer(run). The decorator gets the function object (no parentheses, so it isn't called), and the name run is rebound to whatever the decorator returns.

Higher-order functions are everywhere once you look. In JavaScript, button.addEventListener("click", handler) passes a function to be called later; that's called a callback. Data tools like pandas and Spark are built around map and filter. And many AI frameworks wrap your functions in decorators to turn them into tools a model can call.

Check

What does make_adder(5) evaluate to?

A function. Python prints it as something like <function make_adder.<locals>.adder at 0x...>. You have to call it, make_adder(5)(10), to get a number (15).

Practice 5

What does functools.reduce(lambda a, b: a * b, [1, 2, 3, 4]) return?

HintIt combines left to right: ((1 × 2) × 3) × 4.

24, which is 4! from lesson 5's factorial, with no recursion and no loop in sight. Python 3.8 added math.prod for exactly this.

Where this idea took off

MapReduce, 2004

Google needed to process the whole web: count words across billions of pages, build its search index, analyze logs. Jeffrey Dean and Sanjay Ghemawat noticed that most of these jobs had the same shape: map a function over every record, then reduce the results by key. So they wrote one system that ran the map and reduce functions across thousands of machines and handled crashed machines automatically. Engineers only supplied the two functions. Their 2004 paper says the idea came straight from the map and reduce of Lisp and other functional languages. An open-source copy, Hadoop, powered a generation of "big data" systems, and Spark, its successor, is built on the same higher-order functions you saw in this lesson.

What to remember

  • A higher-order function takes or returns a function. Use one to name a pattern, with a hole for the part that varies.
  • A lambda is a one-expression function. If it needs a second line, use def.
  • Map transforms every item, filter keeps some, reduce combines them. In Python, comprehensions usually read better.
  • A function defined inside another closes over its variables. It remembers the variable, not the value.
  • A decorator is f = decorator(f) with nicer syntax.

Try it in Python

Build a tiny pipeline helper that chains functions, then use it:

def pipeline(*steps):
    def run(x):
        for step in steps:
            x = step(x)
        return x
    return run

clean = pipeline(str.strip, str.lower, lambda s: s.replace(" ", "-"))
print(clean("  Hello World "))    # hello-world
