Switches that flip switches

A transistor is a switch with no moving parts. It has three connections. A voltage on one of them, the gate, decides whether current can flow between the other two. Unlike a light switch, it's controlled by electricity, so the output of one transistor can control another. That's the whole trick. Chain enough of them and you can compute.

The way you wire switches decides what they compute. Put two in a row (in series) and current only gets through if both are closed. Put them side by side (in parallel) and either one is enough.

Real chips use pairs of transistors (a design called CMOS) rather than lamps and batteries, but the idea is the same. The first microprocessor, Intel's 4004 from 1971, had about 2,300 transistors. Large chips today have tens of billions, each one a tiny switch.

Logic gates and truth tables

Engineers don't think in individual transistors. They group a few into a logic gate, a small circuit with a fixed rule for turning input bits into an output bit. A truth table lists that rule for every possible input. Try each gate on the bench above and watch its table.

GateOutput is 1 whenWritten as
NOTthe input is 0 (it flips the bit)¬A, !a, ~a
ANDboth inputs are 1A·B, a && b, a & b
ORat least one input is 1A+B, a || b, a | b
XORthe inputs are differentA⊕B, a ^ b
NANDnot both inputs are 1 (AND, then NOT)¬(A·B)
NORneither input is 1 (OR, then NOT)¬(A+B)

The last column should look familiar. The &, |, ^, and ~ operators in C, Java, JavaScript, and Python are these gates, applied to every bit of a number at once. When you write flags & 0x04, the CPU runs 32 or 64 AND gates side by side.

A truth table needs one row for every combination of inputs. Each input doubles the number of combinations, just like each bit did in lesson 1.

Practice 1

How many rows does the truth table for a 3-input gate have?

HintA 2-input gate has 4 rows. How many patterns do 3 bits have?

Three inputs make 23 = 8 combinations, from 000 to 111.

Check

Which gate outputs 1 when exactly one of its two inputs is 1?

XOR, "exclusive or": one or the other, but not both. Another way to read it: XOR outputs 1 when its inputs differ. That makes it a bit comparator, and you'll see it again in the adder.

One gate to build them all

Here's a surprising fact: you only need NAND. Every other gate, and therefore every digital circuit, can be built from NAND gates alone. That's why the Nand2Tetris course starts its whole computer from a single NAND.

The OR construction works because of De Morgan's laws, two rules you'll use for the rest of your career, usually when simplifying an if condition:

not (A and B)  ==  (not A) or  (not B)
not (A or  B)  ==  (not A) and (not B)

In words: to negate a combined condition, negate each part and swap AND with OR. The OR circuit above computes NAND(¬A, ¬B) = ¬(¬A · ¬B) = A + B.

Practice 2

What's the fewest NAND gates you need to build an AND gate?

HintNAND is AND followed by NOT. How do you undo the NOT?

2: one NAND, then a second NAND with both inputs tied together to act as NOT. The two NOTs cancel out.

Check

A code review asks you to simplify if not (is_admin or is_owner):. Which condition means the same thing?

De Morgan: not (A or B) is (not A) and (not B). "Neither an admin nor the owner." Getting this wrong in an access check is a real security bug, so it's worth checking with a truth table when in doubt.

Adding with gates

Now for the payoff. Adding two single bits has only four cases:

ABA + BCarrySum
00000
01101
10101
112 (10 in binary)10

Look at the last two columns. The sum column is exactly XOR. The carry column is exactly AND. So two gates add two bits. This circuit is called a half adder.

Half adder

Flip A and B. Watch which gate lights up.

It's a "half" adder because it can't accept a carry coming in from the column to its right. When you add multi-digit numbers by hand, every column after the first has three things to add: two digits and a carry. A full adder handles that. It's two half adders chained together, plus an OR gate to combine their carries:

sum   = A ⊕ B ⊕ Cin
carry = (A · B) + ((A ⊕ B) · Cin)
Check

A full adder gets A = 1, B = 1, and carry-in = 1. What are its outputs?

1 + 1 + 1 = 3, which is 11 in binary: sum 1, carry 1. Check with the formula: 1 ⊕ 1 ⊕ 1 = 1, and (1·1) + (0·1) = 1.

A 4-bit adder

To add whole numbers, line up one full adder per bit. Each one's carry-out feeds the next one's carry-in, exactly like carrying a 1 to the next column on paper. This is a ripple-carry adder.

Ripple-carry adder

Set two 4-bit numbers. Try 0111 + 0001 to watch a carry ripple across.

The name comes from the timing: adder 3 can't finish until adder 2 hands it a carry, which waits on adder 1, and so on. For 64 bits that's a long chain of waiting. Real CPUs use smarter designs (like carry-lookahead) that work out the carries in parallel, but they compute the same answer.

Notice what happens to the carry out of the leftmost adder: there's no fifth bit to put it in. That's the overflow from lesson 1, now visible as a wire with nowhere to go.

Practice 3

A 4-bit adder computes 1011 + 0110. What 4-bit result do its four sum outputs show?

Hint11 + 6 = 17, but 4 bits only go up to 15. Or set it up on the adder above.

11 + 6 = 17 = 1 0001. The four sum outputs show 0001, and the extra 1 comes out as the final carry. In unsigned math the true answer is 16 more than what the outputs show.

Subtraction and the ALU

You don't need a separate subtractor. Lesson 1 showed that −B is "flip every bit of B, then add 1." So:

A − B  =  A + (flipped B) + 1

The adder already has a place to put that extra 1: the carry-in of the first full adder, which is otherwise 0. And flipping B on demand is a job for XOR, because x ⊕ 0 = x and x ⊕ 1 = ¬x. Send each bit of B through an XOR gate whose other input is a "subtract" control line. When the line is 0, B passes through unchanged. When it's 1, every bit of B flips, and the same line sets the first carry-in to 1.

Check

To compute A − B, the circuit flips every bit of B and sets the first carry-in to 1. Why the carry-in?

Flipped B plus 1 is −B in two's complement. The carry-in supplies that +1 for free, without any extra adder.

Add a few more operations, like bitwise AND, OR, and XOR, and a selector that picks which result to output, and you have an ALU, the arithmetic logic unit. It's the part of the CPU that actually computes. Alongside its result, it reports flags: single bits describing the result, which later instructions can check.

A 4-bit ALU

Choose an operation. Try 0110 + 0011 and watch the V flag.

FlagSet whenUsed for
Z zerothe result is all zerosif (a == b): subtract and check for zero
N negativethe top bit of the result is 1if (a < b) for signed numbers, along with V
C carrya carry came out of the top bitunsigned overflow and unsigned comparisons
V overflowthe signed result is wrong: two positives gave a negative, or two negatives gave a positivedetecting signed overflow

That's how a comparison like a == b actually runs: the ALU computes a − b, throws the result away, and the next instruction checks the Z flag.

Practice 4

Treating the bits as signed 4-bit numbers, the ALU adds 0110 (6) and 0011 (3). What signed value does the 4-bit result represent?

HintAdd them in binary. In signed 4-bit, the top bit is worth −8.

6 + 3 = 9 = 1001. As a signed 4-bit number that's −8 + 1 = −7. The largest signed 4-bit value is 7, so the answer overflowed, and the ALU sets the V flag to say so.

Remembering: registers and the clock

Every circuit so far forgets instantly: change an input and the output changes with it. A computer also needs to hold values. The trick is feedback. Wire two gates so each one's output feeds the other's input, and the loop keeps itself in one state until something pushes it into the other. That loop, called a latch, stores one bit.

A refined version, the flip-flop, only accepts a new value at one exact moment: when a clock signal ticks. Put several flip-flops side by side, all listening to the same clock, and you have a register, a small group of bits that holds a value between ticks.

A 4-bit register

Change the data bits. The stored value only changes when you tick the clock.
Data in
Stored (output)0000

No ticks yet.

Check

A register holds 0101. You change its data input to 1111 but the clock doesn't tick. What does the register output?

Still 0101. The register only samples its input on a tick. That's what keeps a CPU orderly: every part computes from the values stored at the last tick, and all the results are saved together on the next one.

The clock sets the pace for the whole chip. A 3 GHz processor ticks 3 billion times a second. Each tick lasts about a third of a nanosecond, during which light travels only about 10 centimeters. Every signal in one step of the circuit has to settle before the next tick, which is one reason chips are small.

Practice 5

How long is one clock tick on a 4 GHz processor, in nanoseconds?

Hint4 GHz is 4 billion ticks per second, and a nanosecond is one billionth of a second.

1 ÷ 4,000,000,000 seconds = 0.25 ns (250 picoseconds).

Putting it together: a CPU

You've now seen every major piece of a processor. A simple CPU is these parts wired together:

  • ALU: the adder and friends you built in this lesson.
  • Registers: a few dozen fast storage slots, made of flip-flops, right next to the ALU.
  • Clock: the tick that tells every register when to save.
  • Control unit: reads instructions from memory and sets the control lines, like the ALU's operation select and the "subtract" line.
  • Memory: much bigger and much slower than registers. It holds the program itself, as bytes.

The one piece left is the control unit: how does a list of bytes in memory become "add R0 and R1 and put the result in R3"? That's the next lesson.

When hardware gets it wrong

The Pentium FDIV bug, 1994

Intel's Pentium divided numbers using a lookup table burned into the chip. Five entries out of 1,066 were missing, so certain divisions came out wrong around the fourth significant digit. A math professor, Thomas Nicely, noticed while computing with prime numbers. Software can be patched, but these gates were etched in silicon, and Intel ended up offering replacement chips at a cost of about $475 million. Hardware teams now verify designs with formal proofs and huge test suites before anything is manufactured.

Why clock speeds stopped climbing

For decades, smaller transistors meant faster clocks at the same power. Around 2005 that stopped working (a trend called Dennard scaling broke down): pushing past roughly 4 GHz made chips too hot to cool. So the industry put several CPU cores on one chip instead. That's why your laptop has many cores at a few GHz rather than one core at 20 GHz, and why parallel hardware like GPUs became the engine of modern AI.

What to remember

  • A transistor is a switch controlled by electricity. Series wiring gives AND; parallel gives OR.
  • Gates follow truth tables. Your language's &, |, ^, and ~ are gates applied to every bit at once.
  • NAND alone can build every other gate. De Morgan: negate the parts and swap AND with OR.
  • Sum is XOR, carry is AND. Chain full adders to add whole numbers.
  • Subtract by flipping B with XOR and setting the carry-in to 1.
  • The ALU computes and sets flags (Z, N, C, V) that comparisons and branches use.
  • Feedback loops store bits; registers save new values only when the clock ticks.

Try it in Python

Build everything from one function, nand, and check the 4-bit adder:

def nand(a, b): return 1 - (a & b)
def not_(a):    return nand(a, a)
def and_(a, b): return not_(nand(a, b))
def or_(a, b):  return nand(not_(a), not_(b))
def xor(a, b):  return and_(or_(a, b), nand(a, b))

def full_adder(a, b, c):
    s1 = xor(a, b)
    return xor(s1, c), or_(and_(a, b), and_(s1, c))   # (sum, carry)

def add4(a, b):   # bit lists, least significant bit first
    carry, out = 0, []
    for x, y in zip(a, b):
        s, carry = full_adder(x, y, carry)
        out.append(s)
    return out, carry

>>> add4([1, 1, 0, 1], [0, 1, 1, 0])   # 11 + 6
([1, 0, 0, 0], 1)                        # 0001 with carry out: 17
