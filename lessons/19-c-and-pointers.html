C and pointers

Python hides memory from you: names point at objects, and you never see an address. C shows you everything. This stage uses C to look at what's really happening underneath every program, starting with the idea that trips up everyone at first: the pointer.

    Why C

    C was created by Dennis Ritchie at Bell Labs in the early 1970s to write the Unix operating system, and it's still the language of the layers everything else stands on: the Linux, Windows, and macOS kernels, the CPython interpreter you've been using, SQLite and PostgreSQL, and the firmware in cars and appliances. It's popular there because it maps almost directly onto the machine from stage 1. A C variable is a few bytes at an address; a C operation is a few instructions.

    That closeness has a cost. C doesn't check array bounds, doesn't manage memory for you, and doesn't stop you from reading memory you shouldn't. CMU's 15-213 and Berkeley's CS61C teach it for the same reason this stage does: it shows you what the higher-level languages are doing on your behalf.

    #include <stdio.h>

int main(void) {
    int count = 3;                 // every variable has a fixed type
    for (int i = 0; i < count; i++) {
        printf("hello %d\n", i);
    }
    return 0;
}

    Unlike Python, C is compiled ahead of time to machine code (lesson 5 covers how), and the types are fixed when you write the program.

    Types have sizes

    In C, a type tells the compiler how many bytes a value takes and how to interpret them. On a typical 64-bit machine:

    TypeBytesHolds
    char1one byte: a small integer or one ASCII character
    int4a 32-bit two's complement integer (stage 1, lesson 1)
    long8 on Linux and macOS, 4 on Windowsa larger integer
    double8a 64-bit floating-point number
    int * (any pointer)8a memory address

    The sizeof operator gives the size in bytes: sizeof(int) is 4. Sizes aren't fully fixed by the C standard, which is why long differs between systems, and why careful code uses types like int32_t and int64_t when the exact size matters. Remember that a C int can overflow, unlike a Python int.

    Addresses and pointers

    Every variable lives at some address in memory. The & operator gives you that address, and a pointer is a variable that holds one. The * operator dereferences a pointer: it goes to the address and reads or writes what's there.

    int x = 42;
int *p = &x;     // p holds the address of x. "int *" means "pointer to an int".
*p = 7;          // go to the address in p, and store 7 there. x is now 7.

    This is the same idea as Python names pointing at objects (stage 1, lesson 4), with the arrow made visible and editable. Step through the panel's first four lines to see it.

    Practice 1

    On a 64-bit machine, how many bytes does a pointer take, whatever it points to?

    HintA pointer holds an address. How wide are addresses on a 64-bit machine?

    8 bytes (64 bits). A char *, an int *, and a double * are all 8 bytes; the type only tells the compiler what to expect at the address.

    Check

    After int x = 42; int *p = &x;, what does *p = 7; do?

    The star means "the thing at this address". *p = 7 writes 7 into x, so afterward x is 7 and p is unchanged.

    Arrays and pointer arithmetic

    A C array is exactly the array from stage 3: items side by side in one block. The array's name, used in an expression, turns into a pointer to its first item. And adding 1 to a pointer moves it forward by one item, not one byte: p + 1 on an int * adds 4 to the address, on a double * it adds 8. So indexing is just arithmetic:

    arr[i]  is defined as  *(arr + i)
// address of arr[i] = address of arr + i × sizeof(int)

    That's the formula from the arrays lesson, built into the language. Step through the rest of the panel: p = arr aims p at arr[0], p = p + 2 moves it two ints (8 bytes) along, and *p = 99 overwrites arr[2].

    Practice 2

    An int array arr starts at address 0x1000. What is the address of arr[3]? (Answer in hex, like 0x1004.)

    Hint3 ints × 4 bytes = 12 bytes, and 12 in hex is C.

    0x1000 + 12 = 0x100C. In code: &arr[3] == arr + 3.

    Check

    A double *d holds address 0x2000. What address does d + 1 hold?

    One double is 8 bytes, so d + 1 is 0x2008. That's why pointers have types: the compiler needs the item size to do the arithmetic.

    Pointers and functions

    C passes every argument by value: the function gets a copy. So this swap does nothing to the caller's variables:

    void swap(int a, int b) {   // copies
    int t = a; a = b; b = t;
}
swap(x, y);    // x and y unchanged
    void swap(int *a, int *b) { // addresses
    int t = *a; *a = *b; *b = t;
}
swap(&x, &y);  // x and y swapped

    Passing addresses lets a function change the caller's variables, and it avoids copying big structures: pass an 8-byte pointer instead of a 1 MB array. In fact, an array passed to a function always arrives as a pointer to its first item. That's why C functions that take arrays also take their length: the function can't find it out.

    Check

    Why does the left-hand swap fail?

    Arguments are copied. The pointer version passes copies too, but copies of addresses, and both copies lead to the same variables.

    Strings, and what goes wrong

    C has no string type. A string is an array of char that ends with a zero byte, written '\0', which marks the end. char s[] = "hello" takes 6 bytes: five letters and the terminator. Finding a string's length means walking until the zero, so strlen is O(n). That's exactly what made GTA Online's loading quadratic in lesson 1 of stage 3.

    Practice 3

    How many bytes does char s[] = "hello"; take?

    HintDon't forget the end marker.

    6: five letters plus '\0'. strlen(s) is 5; sizeof(s) is 6. Forgetting the extra byte is a classic off-by-one bug.

    Two dangers follow from all this. First, nothing checks bounds. arr[5] on a 4-item array just computes an address past the end and reads or writes whatever's there. That's undefined behavior: the program might crash, might seem fine, or might be quietly corrupting other data. Copying a long string into a short array this way is a buffer overflow, the bug behind the Morris worm in stage 1. Second, a pointer can be NULL, the address 0, meaning "points nowhere", and dereferencing it crashes the program.

    Check

    In C, what happens when you write to arr[10] on a 4-item array?

    Undefined behavior. It computes arr + 10 and writes there, possibly over another variable or a return address. Tools like AddressSanitizer (gcc -fsanitize=address) catch these during testing, and memory-safe languages like Rust check at compile time.

    When this goes wrong

    The billion-dollar mistake

    In 1965, Tony Hoare was designing the type system for a language called ALGOL W and added the null reference, "simply because it was so easy to implement." It spread into C, C++, Java, C#, JavaScript, and Python (as None). In a 2009 talk he called it his "billion-dollar mistake", estimating the cost of the crashes, vulnerabilities, and debugging it had caused over 40 years. Newer languages like Rust, Swift, and Kotlin make "might be missing" part of a value's type, so the compiler forces you to check before you use it.

    What to remember

    • C maps closely to the machine: variables are bytes at addresses, and types fix their sizes.
    • &x is x's address; a pointer holds an address; *p is the thing it points at.
    • Pointer arithmetic counts in items: arr[i] is *(arr + i).
    • C passes copies. Pass a pointer to let a function change the caller's data.
    • Strings end with '\0'. Nothing checks bounds or null: that's where C's worst bugs come from.

    Try it yourself

    Save this as ptr.c, then build and run it with gcc ptr.c -o ptr and ./ptr (on Windows, install GCC through MSYS2, or paste it into Compiler Explorer or Python Tutor's C mode):

    #include <stdio.h>

int main(void) {
    int arr[4] = {10, 20, 30, 40};
    for (int i = 0; i < 4; i++)
        printf("arr[%d] = %d at address %p\n", i, arr[i], (void *)&arr[i]);
    return 0;      // the addresses go up by 4 each time
}
