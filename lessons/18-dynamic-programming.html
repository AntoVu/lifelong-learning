Dynamic programming

In stage 2, a cache turned fib from exponential to linear. Dynamic programming is that idea made into a method: break a problem into overlapping subproblems, solve each one once, and build the answer from a table. It's behind spell checkers, git diff, DNA comparison, and route planning.

How different are two words?

The edit distance is the fewest single-letter inserts, deletes, and substitutions that turn one word into the other. Step through the table: each cell is built from the three blue cells next to it.

From memoization to tables

Recall the two versions of fib. Naive recursion repeats subproblems exponentially; adding @cache solves each subproblem once. That's top-down dynamic programming: write the recursion, cache the answers. You can also go bottom-up: start from the base cases and fill a table in an order where everything you need is already there:

# top-down: recursion + cache
@cache
def fib(n):
    if n < 2:
        return n
    return fib(n - 1) + fib(n - 2)
# bottom-up: fill a table
def fib(n):
    table = [0, 1]
    for i in range(2, n + 1):
        table.append(table[i - 1] + table[i - 2])
    return table[n]

Both do O(n) work. Bottom-up avoids deep recursion (no RecursionError at n = 5,000) and often makes it obvious how to save memory; here you only ever need the last two entries. Top-down is often easier to write first, because it's just the recursion you'd write anyway.

Not every recursion benefits. DP needs two properties: overlapping subproblems (the same smaller questions come up again and again, as in fib's tree) and optimal substructure (the best answer to the big problem is built from best answers to smaller ones). Merge sort has the second but not the first: its halves never overlap, so caching would save nothing.

A recipe for DP

MIT's 6.006 teaches a checklist for designing any dynamic program. Its name, SRTBOT, is an acronym for:

  • Subproblems: define what a smaller version of the problem is, usually by a prefix, suffix, or amount. Write it as a function, like best(x).
  • Relate: write a recurrence that solves a subproblem from smaller ones, usually by trying every choice for the first or last step.
  • Topological order: make sure subproblems only depend on smaller ones, so there are no cycles (lesson 6!).
  • Base cases: the smallest subproblems, answered directly.
  • Original problem: which subproblem is the actual answer.
  • Time: number of subproblems × work per subproblem.

The last line is the payoff: the running time falls straight out of the design.

Coin change, and why greedy fails

Problem: using coins of given values, make an amount with as few coins as possible. With U.S. coins (1, 5, 10, 25 cents), the obvious strategy works: always take the biggest coin that fits. That's a greedy algorithm, like Dijkstra's. But with coins of 1, 3, and 4, greedy makes 6 as 4 + 1 + 1, three coins, when 3 + 3 uses two. Greedy committed to the 4 and never reconsidered.

DP reconsiders every choice. Subproblem: best(x) = fewest coins to make x. Relation: the last coin used is one of the coin values c, so best(x) = 1 + min(best(x − c)) over the coins that fit. Base case: best(0) = 0. Order: x from 0 up. Time: amount × number of coins.

def min_coins(coins, amount):
    best = [0] + [float("inf")] * amount
    for x in range(1, amount + 1):
        for c in coins:
            if c <= x:
                best[x] = min(best[x], best[x - c] + 1)
    return best[amount]

min_coins([1, 3, 4], 6)    # 2

Check

Why does the greedy strategy fail for coins 1, 3, 4 and amount 6?

Greedy never reconsiders. After taking the 4 it's stuck making 2 from ones. DP tries every possible last coin for every amount, so it can't be trapped by an early choice. Greedy works only when you can prove it does, as Dijkstra did for non-negative edges.

Edit distance

Now the panel's problem. Subproblem: D[i][j] = edit distance between the first i letters of word A and the first j letters of word B. Relation: look at the last letters. Either delete A's last letter, insert B's last letter, or match the two last letters (free if they're equal, a substitution otherwise):

D[i][j] = min(D[i-1][j] + 1,                        # delete a letter from A
              D[i][j-1] + 1,                        # insert a letter from B
              D[i-1][j-1] + (A[i-1] != B[j-1]))     # match, or substitute

Base cases: turning i letters into nothing takes i deletes, so D[i][0] = i, and D[0][j] = j. Order: row by row, left to right, so the cells above and to the left are always ready. Time: one cell per pair of prefixes, constant work each, so O(m × n) for words of length m and n. Following the choices back from the corner gives the actual edits, which the panel lists when the table is full.

Check

What's the running time of the edit distance table for words of lengths m and n?

(m + 1) × (n + 1) cells, each computed in constant time from three neighbors: O(m × n). The plain recursion tries three choices at every step: exponential. Subproblems × work per subproblem, the T in SRTBOT.

Where DP shows up

  • Diff tools like git diff find the longest common subsequence of two files' lines, a close cousin of edit distance.
  • Spell checkers and search suggest words within a small edit distance of what you typed.
  • Biology: the Needleman–Wunsch algorithm (1970) aligns DNA and protein sequences with this same table, with scores for matches and gaps.
  • Speech recognition long relied on the Viterbi algorithm, a DP that finds the most likely sequence of sounds or words.
  • Reinforcement learning, the way game-playing AIs learn, is built on the Bellman equation, the same "best now = best step + best from there" relation.
Check

Which problem is not a good fit for dynamic programming?

The maximum. One pass with no repeated subproblems; there's nothing to reuse, so a table adds nothing. DP pays off when the same smaller questions keep coming up.

Where the name came from

Bellman's camouflage, 1950s

Richard Bellman developed the method at the RAND Corporation, which did research for the U.S. Air Force. In Bellman's autobiography, the story goes that the Secretary of Defense at the time, Charles Wilson, hated the word "research", and "mathematical" even more. So Bellman picked a name nobody could object to: "dynamic" because the problems unfolded over time and the word sounded impressive, and "programming" in its old sense of planning a schedule, not writing code. Bellman wrote that it was "something not even a Congressman could object to." The AI textbook authors Russell and Norvig point out that the story can't be strictly true, since Bellman's first paper using the term (1952) came out before Wilson took office (1953). Either way the name stuck, and it's why a technique about tables of subproblems has a name that describes neither.

What to remember

  • DP = recursion + solve each overlapping subproblem once. Top-down caches; bottom-up fills a table.
  • It needs overlapping subproblems and optimal substructure.
  • Design with SRTBOT: subproblems, relate, topological order, base cases, original problem, time.
  • Greedy commits to choices; DP tries them all, once each. Use greedy only with a proof.
  • Edit distance: D[i][j] from three neighbors, O(m × n).

Try it in Python

def edit_distance(a, b):
    m, n = len(a), len(b)
    D = [[0] * (n + 1) for _ in range(m + 1)]
    for i in range(m + 1): D[i][0] = i
    for j in range(n + 1): D[0][j] = j
    for i in range(1, m + 1):
        for j in range(1, n + 1):
            D[i][j] = min(D[i - 1][j] + 1, D[i][j - 1] + 1,
                          D[i - 1][j - 1] + (a[i - 1] != b[j - 1]))
    return D[m][n]

print(edit_distance("kitten", "sitting"))   # 3
print(edit_distance("flaw", "lawn"))        # 2
