Values, variables, and control flow

You've seen how a CPU runs instructions. Now climb up to the code you actually write. This lesson covers the core of every program, in Python: values, the names that point at them, and the if statements and loops that decide which line runs next.

Values and types

Every value in Python has a type, which decides what you can do with it. These are the ones you'll use constantly:

TypeExamplesUnder the hood (lessons 1 to 3)
int42, -7, 0xFFWhole numbers. Python grows them as needed, so they never overflow.
float3.5, 0.1, 1e964-bit IEEE 754 floating point, with all the rounding from lesson 1.
str"hi", 'café'A sequence of Unicode characters, stored as UTF-8 when written to a file.
boolTrue, FalseOne bit of meaning. In Python it's a kind of int: True + True is 2.
NoneTypeNone"No value here." Functions with no return give back None.
list[1, 2, 3]An ordered collection you can change. More on lists below.

Python's ints are unusual. In Java, an int is 32 bits and wraps around exactly like the 8-bit register in lesson 3 (in C, overflowing a signed int is undefined behavior, which is worse). Python quietly switches to as many bits as it needs, so 2 ** 100 is 1267650600228229401496703205376, exactly. Floats get no such treatment: they're the hardware's 64-bit floats, so 0.1 + 0.2 is still 0.30000000000000004.

Division has two forms. / always gives a float: 7 / 2 is 3.5. // is floor division, which rounds down to a whole number: 7 // 2 is 3. "Down" means toward negative infinity, which surprises people coming from C and Java, where integer division rounds toward zero.

Practice 1

What does -7 // 2 evaluate to in Python?

Hint−7 ÷ 2 is −3.5. Floor division rounds down, toward negative infinity.

−4. Rounding −3.5 down gives −4, not −3. In C and Java, -7 / 2 is −3, because they round toward zero. If you port code between languages, this is a classic source of bugs, for example in code that computes which page or bucket a negative index falls into.

Check

Which line prints False?

0.1 + 0.2 == 0.3 is False, because neither 0.1 nor 0.2 is exact in binary (lesson 1). Compare floats with a tolerance instead: math.isclose(0.1 + 0.2, 0.3) is True.

Variables are names, not boxes

It's common to picture a variable as a box holding a value. In Python, a better picture is a name tag tied to a value. Assignment, x = 5, means "make the name x point at the value 5". It doesn't copy anything.

That explains a line that looks wrong to anyone who knows algebra: x = x + 1. Python works out the right side first, using the current value of x, makes a new value, and then moves the name x to point at it. Run the "Names and values" program on the tracer and watch y stay at 5 when x moves to 6. Then watch the arrows when same = nums runs.

For numbers and strings this difference never shows, because they can't be changed in place (they're immutable). x = x + 1 builds a new number. Lists are mutable: append changes the list itself, and every name pointing at it sees the change. Two names for one object is called aliasing. When you actually want a separate copy, ask for one: same = nums.copy().

Check

What does this print?

a = ["x"]
b = a
b = b + ["y"]
print(a)

['x']. b + ["y"] builds a new list, and the assignment moves b to it. a still points at the original, unchanged. Compare b.append("y"), which would change the shared list and print ['x', 'y']. The rule: assignment moves a name; methods like append change an object.

True, false, and short circuits

Comparisons like ==, !=, <, and >= produce a bool. You combine bools with and, or, and not, the AND, OR, and NOT gates from lesson 2. Python also lets you chain comparisons: 0 < x < 10 means 0 < x and x < 10.

Python is relaxed about what counts as true. In a condition, these values count as false ("falsy"): False, None, 0, 0.0, the empty string "", and empty collections like []. Everything else counts as true. That's why if items: is the usual way to ask "is this list non-empty?"

and and or also short-circuit: they stop as soon as the answer is known. If the left side of and is false, the right side never runs. That isn't only a speed trick. It lets the left side guard the right:

if count != 0 and total / count > 10:   # never divides by zero
    ...

One more detail: and and or return one of their operands, not necessarily True or False. x or y gives back x if it's truthy, and y otherwise. People use that for defaults: name = user_input or "Anonymous".

Practice 2

What does print(0 or "default") print?

HintIs 0 truthy or falsy? or returns the first truthy operand, or the last one.

default. 0 is falsy, so or moves on and returns "default". Watch for this in real code: volume = setting or 50 replaces a deliberate setting of 0 with 50. When 0 is a valid value, write 50 if setting is None else setting.

Check

user might be None. Which condition can never crash with an error about None?

user is not None and user.is_admin. When user is None, the left side is False, and stops, and user.is_admin never runs. Order matters: put the guard first.

Branching

An if statement runs a block only when its condition is true. elif ("else if") adds more conditions, and else catches everything left over. Python checks them from top to bottom and runs only the first match. Then it skips to the end of the whole chain. Run "Branching" on the tracer and notice that lines 3, 6, and 7 never light up.

Python uses indentation to mark which lines belong to a block, where most other languages use braces. Under the hood, each if becomes a compare and a conditional jump, like JZ in lesson 3: if the condition is false, jump past the block.

Check

Someone reorders the Branching program's conditions. What does it print when temp = 95?

if temp >= 60:
    advice = "go for a walk"
elif temp >= 90:
    advice = "stay inside"
else:
    advice = "bring a jacket"

go for a walk. 95 ≥ 60 is true, so the first block runs and the rest of the chain is skipped. The temp >= 90 branch can now never run: any temperature that reaches it already failed temp >= 60. When ranges overlap, check the narrowest one first.

Loops

A while loop repeats its block as long as its condition is true. It's the right tool when you don't know in advance how many times to go around. "While loop" on the tracer adds up the digits of 472 by peeling off the last digit (n % 10) and then dropping it (n // 10), until nothing is left.

Here's that loop compiled to Python bytecode. It's the Countdown pattern from lesson 3: a conditional jump out of the loop, and a jump backward to the test.

  3   L1:     LOAD_NAME                0 (n)
              LOAD_SMALL_INT           0
              COMPARE_OP             148 (bool(>))
              POP_JUMP_IF_FALSE       28 (to L2)     # leave the loop
  ...         (the loop body, lines 4 and 5)
              JUMP_BACKWARD           34 (to L1)     # go back to the test
Practice 3

What does the "While loop" program print? Work it out by hand first, then check it on the tracer.

HintWrite a small table with columns n and total, and add a row each time around the loop.

13 = 2 + 7 + 4. The table: (472, 0) → (47, 2) → (4, 9) → (0, 13). The body runs three times, once per digit, and the test n > 0 runs four times; the last one is false.

A for loop goes through the items of a collection one at a time. "For loop" on the tracer finds the highest score by checking each one. Use for whenever you're walking through something: a list, the characters of a string, the lines of a file. It can't accidentally loop forever, and there's no counter to get wrong.

To loop over numbers, use range. range(start, stop, step) starts at start and stops before stop. So range(5) is 0, 1, 2, 3, 4: five numbers, matching how list indexes start at 0. Getting the end wrong by one is so common it has a name, the off-by-one error.

Practice 4

What numbers does for i in range(2, 10, 3): print(i) print? List them in order.

HintStart at 2 and add 3 each time. Stop before reaching 10.

2, 5, 8. The next value would be 11, which isn't below 10, so the loop ends.

Two keywords change a loop's flow from inside. break leaves the loop immediately. continue skips the rest of this pass and goes on to the next one.

Practice 5

What does this print?

total = 0
for i in range(1, 101):
    total += i
print(total)
HintIt adds 1 + 2 + ... + 100. Does 101 get added? Pair the first and last numbers: 1 + 100, 2 + 99, ...

5050: 50 pairs that each add to 101. range(1, 101) stops at 100, which is exactly why the stop value is 101. Python can also do this in one line: sum(range(1, 101)).

Check

Which loop never ends?

while i != 5 with steps of 2. i goes 0, 2, 4, 6, 8, ... and jumps right over 5. It's the same trap as the Countdown program subtracting 2 in lesson 3, except Python ints don't wrap around, so it never stops. Prefer < or > over != in loop conditions.

When this goes wrong

The Zune freeze, December 31, 2008

At midnight going into the last day of 2008, every Microsoft Zune 30 music player froze. The clock code turned a count of days since 1980 into a year with a loop like this:

while (days > 365) {
    if (IsLeapYear(year)) {
        if (days > 366) { days -= 366; year += 1; }
    } else {
        days -= 365; year += 1;
    }
}

On day 366 of a leap year, days was exactly 366. The outer test was true, but the inner test was false, so nothing changed, and the loop ran forever. The fix for owners was to wait: on January 1, the count moved past it and the players started normally. Tracing that one input by hand would have found it.

Apple's "goto fail", 2014

Apple's code for checking secure connections had a series of if statements, each one jumping to the error handler on failure. A duplicated line slipped in:

if ((err = SSLHashSHA1.update(&hashCtx, &signedParams)) != 0)
    goto fail;
    goto fail;   /* always runs: it isn't part of the if */

Without braces, only the first goto fail belongs to the if. The second always runs, skipping the final signature check while err still said "no error". For over a year, iPhones and Macs accepted forged certificates for these connections. Python's indentation rules make this exact mistake impossible, and many style guides for C-like languages now require braces on every if.

What to remember

  • Every value has a type. Python ints never overflow; floats are the hardware's 64-bit floats.
  • / gives a float. // rounds down, toward negative infinity.
  • Assignment ties a name to a value. It never copies. Two names can share one mutable object.
  • and and or short-circuit. Put the guard first.
  • An if/elif chain runs only the first match. Check narrow cases first.
  • Use for to walk through things and while when you don't know how many passes you need. range stops before its end.
