Arrays, linked lists, stacks, and queues

The last lesson claimed some list operations are cheap and others expensive. Here's why. There are two basic ways to lay a sequence out in memory, and every operation's cost follows from which one you picked.

Arrays

Memory, as stage 1 showed, is one long row of numbered bytes. An array stores its items side by side in one block of it. If every item takes the same number of bytes, the address of item i is simple arithmetic:

address of xs[i] = address of xs[0] + i × (size of one item)

One multiplication and one addition, whether the array has ten items or ten million. That's why indexing is O(1), and why it's called random access: any item costs the same. (A Python list stores 8-byte references to its objects, not the objects themselves, so every slot is the same size even when the items aren't.)

The price is paid when the order changes. To insert at the front, every item has to move one slot to the right to make room. Press "Add to front" above and count the highlighted cells: O(n).

Practice 1

An array of 8-byte items starts at address 1000. At what address is xs[5]?

HintItem 0 is at 1000. Each item after it is 8 bytes further along.

1000 + 5 × 8 = 1040. This is also why indexes start at 0 in most languages: the index is the distance from the start.

Arrays that grow

A raw array has a fixed size, since the memory right after it may belong to something else. A dynamic array (Python's list, Java's ArrayList, C++'s vector) hides that by reserving extra room, its capacity. Appending fills a spare slot: O(1). When it's full, it allocates a bigger block and copies everything over: O(n), but rarely.

The trick is to grow by a multiple, like doubling. Then each expensive copy is followed by as many cheap appends as there were items, so the cost averages out to a constant per append. That average over a sequence of operations is called amortized cost: append is amortized O(1). Watch the capacity in the panel above as you keep pressing "Add to end". (CPython grows lists by about an eighth each time rather than doubling; any constant factor gives the same O(1) average.)

Practice 2

An empty dynamic array starts with capacity 1 and doubles whenever it's full. How many item copies happen in total while appending 8 items?

HintIt resizes from 1 to 2, then 2 to 4, then 4 to 8. Each resize copies the items already there.

1 + 2 + 4 = 7 copies for 8 appends, less than one per append. In general, the copies for n appends add up to less than 2n, so the average stays constant however large the list gets.

Linked lists

A linked list gives up the single block. Each item lives in its own small object, a node, that also holds a reference to the next node. The list itself only remembers the first one, the head:

class Node:
    def __init__(self, value, next=None):
        self.value = value
        self.next = next

head = Node(1, Node(2, Node(3)))   # 1 → 2 → 3

head = Node(0, head)               # add to front: O(1), nothing moves

Adding or removing at the front just changes a reference or two. But there's no arithmetic to find item i: you start at the head and follow next i times. Reading is O(n), and so is appending, unless the list also keeps a reference to its last node (a tail), which makes append O(1).

OperationArray (dynamic)Linked list (head only)
Read item iO(1)O(n)
Add or remove at frontO(n)O(1)
Add at endamortized O(1)O(n), or O(1) with a tail reference
Search for a valueO(n)O(n)
Practice 3

Starting at the head, how many times must you follow a next reference to reach the item at index 4?

HintThe head is index 0, and you're already there.

4: 0 → 1 → 2 → 3 → 4. Reaching index i takes i steps, which is why indexing a linked list is O(n).

Check

Which operation is O(n) for an array but O(1) for a linked list?

Inserting at the front. The array shifts every item; the linked list makes one new node and points it at the old head.

On paper, linked lists look great for lots of inserting. In practice they're often slower than arrays even then, because of the caches from stage 1. An array's items sit next to each other, so reading one pulls its neighbors into the cache for free. A linked list's nodes are scattered across memory, and following each next can mean a fresh trip to RAM, hundreds of clock ticks. Big-O counts steps; it doesn't see that some steps are 100 times slower than others.

Stacks

A stack is a collection where you only touch the top: push adds an item, pop removes the most recently added one. Last in, first out (LIFO). You've already met the most important one, the call stack. A Python list is a perfect stack, because append and pop() both work at the cheap end:

stack = []
stack.append("a")     # push
stack.append("b")
stack.pop()           # 'b'  (last in, first out)

Stacks fit any problem where the most recent unfinished thing must be finished first: undo history, the browser's back button, evaluating nested expressions, and checking that brackets match. For brackets, push each opener; on each closer, pop and check it matches.

Practice 4

Starting with an empty stack: push 1, push 2, pop, push 3, push 4, pop, pop. What does the last pop return?

HintWrite the stack as a list after each step. The pops return 2, then 4, then...

[1] → [1, 2] → pop 2 → [1] → [1, 3] → [1, 3, 4] → pop 4 → pop 3. Only 1 is left.

Check

Using the stack method for brackets, which string is balanced?

{[()]}: each closer matches the opener on top of the stack, and the stack is empty at the end. Code editors, compilers, and the interpreter from stage 2 all do this check.

Queues

A queue is first in, first out (FIFO): you add at the back and remove from the front, like a line at a store. Queues show up wherever work must be handled in arrival order: print jobs, web requests waiting for a server, messages between programs, and breadth-first search in lesson 6.

Don't use a list for this. list.pop(0) removes from the front, which shifts every other item: O(n). Python's collections.deque ("deck", a double-ended queue) adds and removes at both ends in O(1):

from collections import deque

q = deque()
q.append("first")     # join the back
q.append("second")
q.popleft()           # 'first' (first in, first out)
Practice 5

Starting with an empty queue: add a, add b, add c, remove, add d, remove. What does the last remove return?

HintRemovals come from the front, in the order things were added.

The first remove returns a, the second returns b. The queue still holds c and d. A stack doing the same steps would have returned c, then d.

Check

A server keeps waiting requests in a Python list, adds new ones with append, and takes the oldest with pop(0). With 100,000 waiting, it gets slow. Why?

Each pop(0) moves all the other items one slot left: 100,000 moves per request. deque.popleft() is O(1). The fix is one import and two renamed method calls.

When the textbook answer is wrong

Stroustrup's vector vs. list experiment

Bjarne Stroustrup, who created C++, likes to pose a puzzle that came from Jon Bentley: insert random numbers into a sorted sequence, keeping it sorted, then remove items from random positions. Which is faster, an array (C++'s vector) or a linked list? The textbook says linked list, because inserting into an array shifts items. Stroustrup's measurements showed the array winning by a wide margin, and by more as n grew. Both structures first have to find the position by walking from the start, and walking an array runs at full cache speed while walking a list chases pointers all over memory. Stroustrup's own conclusion wasn't "never use linked lists" but "measure, and remember the machine": Big-O tells you how cost grows, not what each step costs.

What to remember

  • Arrays store items side by side: O(1) indexing by arithmetic, O(n) inserting at the front.
  • Dynamic arrays grow by a constant factor, so append is amortized O(1).
  • Linked lists chain nodes: O(1) at the head, O(n) to reach item i, and poor cache behavior.
  • Stack (LIFO): use a list's append and pop(). Queue (FIFO): use collections.deque.
  • Never pop(0) or insert(0, x) in a loop over a big list.

Try it in Python

A bracket checker with a stack:

def balanced(text):
    pairs = {")": "(", "]": "[", "}": "{"}
    stack = []
    for ch in text:
        if ch in "([{":
            stack.append(ch)
        elif ch in pairs:
            if not stack or stack.pop() != pairs[ch]:
                return False
    return not stack

print(balanced("{[()]}"), balanced("([)]"))    # True False
