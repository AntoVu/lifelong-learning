Objects and classes

The last lesson hid data behind functions. Objects go one step further: they bundle data together with the functions that work on it, and they can change over time. Most of the code you'll read at work, in Python, Java, C#, JavaScript, or Swift, is organized this way.

Objects bundle data and behavior

You've been using objects all along. In Python, every value is an object: it has a type, some data, and methods, functions attached to it that you call with a dot. "hi".upper() calls a method of a string. nums.append(3) calls a method of a list, and that method changes the list's data.

Two ideas make objects more than a convenience:

  • Encapsulation. An object's data and the code that works on it live together, behind the object's methods. That's the abstraction barrier from the last lesson, built into the language.
  • State. An object can change over time while staying the same object. A bank account is still the same account after a deposit, with a new balance.

Classes

A class is a blueprint for a kind of object. Each object made from it is an instance.

class Account:
    def __init__(self, owner):          # runs when you create an instance
        self.owner = owner              # instance attributes: each object gets its own
        self.balance = 0

    def deposit(self, amount):          # a method
        self.balance = self.balance + amount
        return self.balance

a = Account("Ada")                      # create an instance: calls __init__
a.deposit(100)                          # 100

Calling the class, Account("Ada"), creates a new empty object and runs __init__ on it to fill it in. The attributes it sets with self.owner = ... belong to that one object. Step through "Two accounts" and watch the frame for Account.__init__() appear twice, once per object.

Methods and self

How does deposit know which account to change? Through its first parameter, self. When you write a.deposit(5), Python finds deposit in a's class and calls it with a as the first argument:

a.deposit(5)
Account.deposit(a, 5)      # exactly the same call

So self isn't magic or a keyword. It's an ordinary parameter, named self by convention, that receives the object the method was called on. In the tracer, every method frame has a self with an arrow to its object. Java, C#, and JavaScript do the same thing but hide the parameter and call it this.

Check

Inside deposit, during the call b.deposit(30), what is self?

b. The call is really Account.deposit(b, 30), so self is b and amount is 30. Step to that call in the tracer and follow self's arrow.

Class attributes and lookup

Attributes can also live on the class itself, shared by every instance:

class Account:
    interest = 0.02            # a class attribute: one value, shared

a, b = Account(), Account()
a.interest                     # 0.02, found on the class

When you read a.interest, Python looks in a fixed order: first the instance's own attributes, then its class, then the class's base classes (next section). The first match wins. Assigning, though, always writes to the instance: a.interest = 0.10 gives a its own attribute, which then hides the class's.

Check

Starting from the code above, what does this print?

a.interest = 0.10
Account.interest = 0.04
print(a.interest, b.interest)

0.1 0.04. a finds its own attribute first. b has none, so it finds the class's, which is now 0.04.

This lookup rule has a famous trap. A mutable class attribute is shared by every instance, so changing it in place changes it for all of them:

Inheritance and composition

A class can be built from another one. A subclass inherits everything from its base class, and changes only what's different:

class CheckingAccount(Account):     # a CheckingAccount is an Account...
    fee = 1                         # ...that charges a fee on withdrawals

Step through "Inheritance". When c.withdraw(10) runs, Python doesn't find withdraw on c or on CheckingAccount, so it keeps going up to Account. Inside, self.fee is looked up starting from c again, and this time it's found on CheckingAccount: 1, not 0. Code in the base class automatically uses the subclass's values. When a subclass needs to extend a method rather than replace it, it calls the original with super().withdraw(amount).

HintThe balance starts at 50. Which fee does self.fee find for a CheckingAccount?

50 − 10 − 1 = 39. The method is written once, in Account, and the subclass changes its behavior just by supplying a different fee.

Inheritance means "is a": a checking account is an account, and should work anywhere an account does. When the relationship is "has a", use composition instead: give one object an attribute that holds another. A bank isn't an account; it has accounts. Step through "Objects in objects" to see a Bank holding a list of Accounts. Many experienced designers favor composition, because inheritance ties a subclass to every detail of its base class.

Special methods

Methods with double underscores, like __init__, are special methods that Python calls for you. Define them, and your objects work with Python's built-in syntax:

class Rational:
    def __init__(self, n, d):
        self.n, self.d = n, d

    def __add__(self, other):                  # x + y
        return Rational(self.n * other.d + other.n * self.d, self.d * other.d)

    def __eq__(self, other):                   # x == y
        return self.n * other.d == other.n * self.d

    def __repr__(self):                        # how it prints
        return f"Rational({self.n}, {self.d})"

Rational(1, 2) + Rational(1, 3)                # Rational(5, 6)

That's last lesson's fractions as a class. The constructor and selectors became __init__ and attributes, and add_rational became +. Without __eq__, == only checks whether two names point at the same object, so two separate objects with equal fields compare unequal.

The special method __iter__ makes an object work in a for loop. The easiest way to write it uses yield, which turns a function into a generator: it hands back one value at a time, pausing in between, instead of building a whole list.

Practice 5

What does list(Countdown(3)) return?

class Countdown:
    def __init__(self, start):
        self.start = start

    def __iter__(self):
        n = self.start
        while n > 0:
            yield n
            n -= 1
HintEach yield produces one item. The loop stops when n reaches 0.

[3, 2, 1]. list() asks the object for an iterator, then pulls values until the generator finishes. Because values are produced on demand, a generator can even describe an endless sequence.

Check

A class Point has an __init__ that sets self.x and self.y, and no other methods. What does Point(1, 2) == Point(1, 2) give?

False: they're two different objects, and the default == checks identity. Add __eq__, or put @dataclass above the class, which generates __init__, __eq__, and __repr__ for you.

When this goes wrong

Java's Stack, 1996

Java 1.0 shipped a Stack class built by inheriting from Vector, its growable array. That saved writing code, but a stack is not a kind of array. Because of the inheritance, every Stack also has all of Vector's methods, so any code can insert into the middle of a stack or read item 7, breaking the one rule that makes it a stack: last in, first out. Java can never remove those methods without breaking old programs, so its documentation now steers people to a different interface, Deque, instead. A stack that had an array (composition) could have hidden it.

What to remember

  • Objects bundle data (attributes) with behavior (methods), and can change state over time.
  • A class is a blueprint. Calling it creates an instance and runs __init__.
  • obj.method(x) is Class.method(obj, x). self is just the first parameter.
  • Lookup order: instance, then class, then base classes. Assignment writes to the instance. Don't put mutable values on the class.
  • Inherit for "is a", compose for "has a". When in doubt, compose.
  • Special methods hook objects into Python's syntax: +, ==, printing, and for.

Try it in Python

dataclass writes the boring methods for you:

from dataclasses import dataclass

@dataclass
class Point:
    x: float
    y: float

    def dist(self, other):
        return ((self.x - other.x) ** 2 + (self.y - other.y) ** 2) ** 0.5

p, q = Point(0, 0), Point(3, 4)
print(p)               # Point(x=0, y=0)
print(p.dist(q))       # 5.0
print(p == Point(0, 0))   # True
